# M1 Dashboard Frontend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A local monitoring dashboard showing:
- the live 5-minute windows: countdown, TWAP vs price to beat, the Up/Down book, Binance and Coinbase;
- system health: feeds, clock, geoblock, recorder and safety checks;
- recording progress toward the M1 gate;
- window history with per-window charts;
- Pause, Resume and Kill controls.

**Architecture:**
- A TanStack Start (React 19, TypeScript, Vite 8) app in `frontend/`. It talks **only** to the Rust API at `http://127.0.0.1:8787`: REST through TanStack Query, live pushes over `/api/ws`.
- It uses no server functions and no database access.
- The API types are the ts-rs files generated by the backend into `frontend/src/api/generated/`. They are never hand-edited.

**Tech Stack:**
- Framework: `@tanstack/react-start` 1.169.x, `@tanstack/react-router` 1.170.x, `@tanstack/react-query` 5.x, React 19.3, Vite 8, TypeScript 5.x.
- Package manager and runtime: pnpm, Node ≥ 22.12.
- Charts: Recharts.
- Tests: Vitest with @testing-library/react and jsdom, Playwright for the smoke test.

**Spec:**
- `CLAUDE.md` §4, Frontend.
- The backend plan: `docs/superpowers/plans/2026-10-26-m1-recorder-backend.md`, Task 9 (routes) and Task 1 (`dto.rs`).

## Global Constraints

- Only these API routes exist:
  - `GET /api/live`
  - `/api/health`
  - `/api/stats`
  - `/api/windows?asset&limit&before`
  - `/api/windows/{slug}`
  - `/api/windows/{slug}/series`
  - `POST /api/control/{pause|resume|kill}` with body `{reason?, acknowledge?}` → `ControlResponse`
  - `GET /api/ws`, which pushes `LiveSnapshot` JSON frames
- The API base comes from `import.meta.env.VITE_API_URL`, default `http://127.0.0.1:8787`.
- Decimal fields arrive as **strings**. Format them for display; never do arithmetic on them as floats except for chart plotting.
- Times arrive as epoch ms (`*_ms`) or epoch seconds (`*_ts`, `ts`). Display them in the browser's local time, with UTC in the title or tooltip.
- **The dashboard never places orders.** Its only mutating calls are pause, resume and kill.
- Dev server runs on port 3000 (the backend's CORS origin is `http://localhost:3000`).
- **Dark and light themes:** colours are defined as CSS custom properties on `:root`, with a `prefers-color-scheme: dark` override.
- Plain CSS modules or one `app.css`. No UI kit.
- **Charts:**
  - Before writing chart code, load the `dataviz` skill if your environment lists it.
  - Charts use the project's CSS tokens.
  - Lines: TWAP is the primary series; price-to-beat is a dashed reference line; Chainlink, Binance and Coinbase are secondary series.
- Every page must render a sensible empty or loading state when the backend is down: a banner reading "Backend unreachable at <url>".

## Review Focus

1. **The backend restarts while the dashboard is open.** The WebSocket drops. Expected: a "Reconnecting…" badge, reconnecting with backoff (1 s → 10 s max), and the last snapshot stays visible but greyed. Test: Task 2, `useLive reconnects after close`.
2. **Resume is refused by the backend** (safety checks failing, or an acknowledgement required). Expected: the error text is shown inline in the dialog, and the state doesn't change optimistically. Test: Task 3, `resume shows backend error`.
3. **Null-heavy data.** Early in a session most `LiveWindow` and `WindowRecord` fields are null. Expected: "—" placeholders and no `NaN` or `Invalid Date`. Test: Task 3, `live card renders all-null window`.
4. **A negative countdown.** After `end_ts`, `secs_left` is negative. Expected: the card shows "ended, awaiting resolution" and never a negative timer. Test: Task 3, `countdown clamps after end`.
5. **A long history list.** Expected: paginated with `before=<last start_ts>` and "Load more"; nothing loads unbounded. Test: Task 4, `windows list paginates with before`.

**Interfaces — Produces:**

```ts
export type LiveStatus = "connecting" | "open" | "reconnecting";
export function useLive(): { snapshot: LiveSnapshot | null; status: LiveStatus; lastMessageMs: number | null };
// opens `${API_URL.replace(/^http/, "ws")}/api/ws`; on message: JSON.parse → snapshot; on close/error: status "reconnecting",
// retry after min(1000 * 2^attempt, 10000) ms; resets attempt on open. Also seeds from GET /api/live once on mount.
// One shared connection per app: implemented via a React context `LiveProvider` in __root.tsx.
export function LiveProvider(props: { children: React.ReactNode }): JSX.Element;
```

### Task 3: Live page, Health page, control panel

**Files:** `src/routes/index.tsx`, `src/routes/health.tsx`, `src/components/{WindowCard, FeedTable, SafetyPanel, ControlPanel, GateProgress}.tsx`, `tests/live.test.tsx`, `tests/health.test.tsx`.

**Behaviour:**

- **Live (`/`)** shows one `WindowCard` per `snapshot.windows`, ordered btc, eth, sol. A card shows:
  - the asset, and the slug as a link to `/windows/{slug}`;
  - a countdown, computed from `end_ts*1000 - Date.now()` and re-rendered every 250 ms. After the end it shows "ended, awaiting resolution".
  - the price to beat and the current TWAP, with the signed difference (TWAP − PTB) in USD and bp, coloured green if ≥ 0 (Up leading) and red otherwise.
  - Chainlink, Binance (USD) and Coinbase mids.
  - Up bid/ask and Down bid/ask, as ¢.
  - "TWAP age", from `twap_ts_ms`.
  - A mini sparkline of the TWAP for the current window. Seed it once from `/api/windows/{slug}/series`, then append live points from snapshots.
- **Health (`/health`):**
  - **`FeedTable`:** source, enabled, connected, last message ago, msgs/s, reconnects, last error, and a stale flag. Stale rows are tinted red; disabled rows are greyed with the note "disabled (no credentials)" for polybolt.
  - **Clock:** the offset in ms, with the threshold.
  - **Geoblock:** country and blocked.
  - **Recorder:** file, records, MB, dropped, last flush ago.
  - **Counts:** sleep events and book resyncs.
  - **`SafetyPanel`:** each check with ✓/✗ and the `reasons` list.
  - **`GateProgress`:** from `/api/stats` (refetched every 10 s):
    - `windows_with_twap / gate_target_windows`, as a progress bar labelled "M1 gate: N / 500 windows with TWAP";
    - the TWAP-match tally: match, mismatch, pending;
    - recorded hours and sessions.
  - **`ControlPanel`:** the current mode, stop kind and reason, with three buttons:
    - **Pause:** a confirm dialog with an optional reason, then `postControl("pause")`.
    - **Resume:** a confirm dialog that shows *why it stopped* (`control.reason`). If `control.needs_ack`, an "I acknowledge: {reason}" checkbox must be ticked before Confirm is enabled. Sends `postControl("resume",{acknowledge})`.
    - **Kill:** a red button, a confirm dialog that requires typing `KILL`, then `postControl("kill")`.
    - After any response: if `ok === false`, show `error` inline in the dialog and keep it open. If ok, close and show a toast "Mode: {state.mode}". No optimistic state; the next WebSocket snapshot drives the UI.

- [ ] **Step 1: Write the failing tests:**
  - `live card renders all-null window`: a `LiveWindow` with only asset, slug and ts fields renders "—" for each value, with no "NaN" and no "Invalid".
  - `countdown clamps after end`: with `end_ts` in the past, the card shows "ended, awaiting resolution".
  - `twap delta colours`: with TWAP > PTB the delta element has `data-dir="up"`; with TWAP < PTB it has `data-dir="down"`.
  - `feed table marks stale`.
  - `safety panel lists reasons`.
  - `gate progress shows N / 500`.
  - `resume requires ack checkbox when needs_ack`: Confirm stays disabled until the checkbox is ticked.
  - `resume shows backend error`: `postControl` is mocked to resolve `{ok:false,error:"safety checks failing: clock offset 63.1 ms > 50 ms",state}`. The dialog stays open and shows that text.
  - `kill requires typing KILL`.
- [ ] **Step 2: Run them to make sure they fail.** Run `pnpm test`. Expected: FAIL.
- [ ] **Step 3: Implement** the pages and components.
- [ ] **Step 4: Run them to make sure they pass.** Run `pnpm test && pnpm typecheck && pnpm build`. Expected: PASS.

### Task 4: Windows history and window detail

**Files:** `src/routes/windows.index.tsx`, `src/routes/windows.$slug.tsx`, `src/components/WindowChart.tsx`, `tests/windows.test.tsx`.

**Behaviour:**

- **`/windows`:**
  - An asset filter (all, btc, eth, sol), stored in the URL search params.
  - A table with columns:
    - start (local time), asset, status;
    - PTB ours, final ours, and outcome ours;
    - Gamma final, and a TWAP match badge (✓ green, ✗ red, … pending, — n/a);
    - winner;
    - resolution latency (`resolution_seen_ms/1000 - end_ts`, in s);
    - coverage (`coverage_secs/300` as %);
    - TWAP source.
  - Fetches `limit=50`. "Load more" fetches with `before = last row's start_ts` and appends.
- **`/windows/$slug`:**
  - A header with all the `WindowRecord` fields.
  - **`WindowChart`:** a Recharts line chart over `series`. The x-axis is seconds into the window (0–300). It shows TWAP, Chainlink, Binance USD and Coinbase, plus a dashed horizontal line at the price to beat (ours, falling back to Gamma).
  - A second small chart: Up bid/ask over time, in ¢.
  - Empty series → "No series recorded for this window (app was not running)."

  - `windows list paginates with before`: the mocked fetch returns 50 rows. Clicking "Load more" calls `/api/windows?limit=50&before=<last start_ts>`, and the table shows 100 rows.
  - `match badge states`: the true, false and null cases.
  - `detail renders empty-series message`.
  - `chart maps ts to seconds into window`: with `series[0].ts = start_ts + 5`, the first point has x = 5.
